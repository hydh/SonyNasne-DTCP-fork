# XCode ファームウェア DRM モジュール解析 第17段

2026-11-15。第16段で残った未確定点 — **KO (鍵オブジェクト) の素材欄の書き手と、SECUREDTS の実効鍵の最終的な出所** — に重点を絞る段。第16段までに DRMCTRL の下流 (束縛 `0x261B7C`、暗号セットアップ `0x15490C` のコマンドパケット構築、ハンドラ表 4 エントリ) はほぼ判明したが、KO の素材欄 (+0x94/+0xA4/+0x154、+0x1E0/+0x1E4、+0x38C/+0x390) と能力フラグ (+0x10)・状態 (+0x0C) の書き手は、実読した全関数の範囲に存在しなかった。AKE 素材はセッションオブジェクト側に在り、KO への橋渡しは読み範囲の外にある。本段はその橋渡しを追う。

手法は第9段の M1–M6 を踏襲 (Ghidra 実読を主とし、静的データはイメージのバイト列から直接読んで照合)。素材は開発側作業領域 `2026-11-13-fw-drm/phase17/` (Ghidra プロジェクト `ghp17` = 第2 FW、`ghp17m` = 主 FW、いずれも phase16 プロジェクトの複製)。アドレス表記は各イメージのロードベース基準 (主 FW = 0、第2 FW = 0xB00000) で、ファイルオフセットと一致する。DRMCTRL 系ライブラリのデータ参照は +0x100000 ビューであり、表・文字列・リストの実内容は「コード上の参照アドレス − 0x100000」のファイルオフセットにある (第16段で実測確認済み)。

用語は第16段を引き継ぐ: **KO (鍵オブジェクト)** = DRMCTRL 文脈 (表 `0x69735C` のエントリが指す構造) の +0x148 にインラインで置かれる 0x3F8 バイトの作業域。**セッションオブジェクト** = KO +0x48 のポインタが指す大きなオブジェクトで、AKE 実体 (gen_kauth / setexchgkey) が操作するセッション文脈 (+0x10C20 起点) を内包する。

## 2. 課題と入口

### 入口 (1) `uist_drmctrl` タスク本体の入口同定

第16段の残件 1 の本線。文脈ごとに生成される `uist_drmctrl` タスクが KO 素材の書き手の残る候補であるが、タスク生成の第1引数は RAM のタスク制御ブロックであり、第16段では入口を同定できなかった。本段では:

- DRMCTRL ライブラリ内のタスク生成呼出し (drmctrl_open の委譲・タスク生成を含む) を全て洗い、渡されるタスク制御ブロック/記述子のテンプレートと入口ポインタ欄の出所を追う。
- 名前文字列 "uist_drmctrl" の参照を両アドレスビュー (ベース 0 / +0x100000) で追い、名前引き機構 (「操作名+引数」の名前記述子を名前引きヘルパに渡す方式が本 FW に実在する) 経由の登録・解決があれば、その経路から入口を確定する。
- タスク生成サービス `0xB082E8` (ID 引き、第10段で同定) の DRMCTRL 文脈での使われ方も確認する。

### 入口 (2) KO 素材欄の書き手 (対象を絞った追跡)

変位 census の全数否定は方法限界が実測済みのため使わず、対象を絞った実読で追う:

- KO の確保・初期化サイト (drmctrl_open 内外) を起点に、KO ポインタが格納される全ての場所と、KO 基底を参照する関数を列挙し、各関数に素材欄 (+0x94/+0xA4/+0x154、+0x1E0/+0x1E4、+0x38C/+0x390) や能力フラグ (+0x10)・状態 (+0x0C) への書込みがあるかを実読で判定する。
- AKE 側からの橋渡し: DRMCTRL 文脈が所有する AKE セッション文脈と KO の間で素材を複写する処理があるか。gen_kauth / setexchgkey の出力の格納先を追い、KO 欄へ届くか判定する。
- 中核計算 `0x1FED1C` (第6・7段: gen_kauth が文脈フィールドを入力して 12 バイトの生成値を出す) の入力文脈フィールドの初期化側 (起源) も、KO へ繋がる範囲で追う。

### 入口 (3) セッションオブジェクト +0x4000 のパケット宛先

第16段の残件 3。暗号セットアップ `0x15490C` がセッションオブジェクト +0x4000 に組む 0x28 バイトのコマンドパケット (ヘッダ 02 09 01 …、KO +0x154 の 16 バイトの平文複写を含む) を読む側を同定する。`uist_drmctrl` タスク自身か、エンジン-facing の別タスクか。入口 (1) と交差する可能性が高い。

### 入口 (4) 余力項目

- DRMCTRL 文脈スロット欄 +0x49C/+0x4B4 の消費者 (第16段の残件 2 の一部。+0x4B8 の消費者は `0x20D918` と確認済み)。
- ハンドラを持たないモード (0x100000/0x200000) の close 側スロット解放と、`0x2629F4` の解放側呼出し元。
